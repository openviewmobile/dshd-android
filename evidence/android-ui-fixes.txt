# Android 界面/插件问题分析与修复（2026-11-09）

## 已修复

1. Chromium 92 缺 URL.canParse / URL.parse
   - 现象：进入插件详情白屏，logcat `TypeError: URL.canParse is not a function`。
   - 修复：dsh-index.html（APK 资源 + rootfs frontend）增加 polyfill。
   - 文件：app/app/src/main/assets/dsh-index.html
           scripts/patch-rootfs-webview.sh

2. rootfs 内 AppleDouble `._*.json`
   - 现象：`Plugin metadata ... locale/._de.json must use a language id`。
   - 根因：macOS 文件带 com.apple.provenance，BSD tar 存入 xattr，Android tar 解出 `._name`。
   - 修复：host 侧用 `COPYFILE_DISABLE=1 tar --no-xattrs` 重新打包；rootfs 内清理 `._*`。
   - 文件：scripts/pack-rootfs.sh

3. 插件安装 spawn pnpm ENOENT
   - 根因：Host PATH 不含 /opt/node24/bin，rootfs 也没有 pnpm。
   - 修复：rootfs 内置 pnpm 10.34.9 + /opt/node24/bin/pnpm wrapper；Host PATH 前移。
   - 文件：HostKeepAliveService.java
   - 验证：pnpm 输出 `+ dsh-plugin-whale-pet ^0.2.9`。

## 已修复：root Include live reload

插件安装/启用/停用后报：
`dsh: profile reload requires the root Include entry`

根因：`mountRootInclude()` 用 `ctx.get("loader")` 取 loader；Android web profile
上该服务查询可能为 undefined，而 `ctx.loader` 已是活的 loader，函数于是提前
return，root Include 没有写入 `bootstrapIncludes`。之后 HMR 的
`recompose()` 必然找不到 entry。

修复：
- `const loader = ctx.get("loader") ?? ctx.loader;`
- reload 时 `bootstrapIncludes.get(ctx) ?? loader entries 中的 include`。

复现：`scripts/patch-rootfs-appboot.sh`。
验证：启用智能体团队后 3 个组件立即运行中；停用后立即已关闭；第三方
小鲸鱼安装、立即启用、卸载均无需重启（截图 ui-29 ~ ui-36）。

## 2026-11-09 第二轮：Android Agent 工具默认不可用

现象：
- 新会话默认“工作区内修改”，执行 shell 报
  `Error: sandbox mode "workspace-write" ...`；glob 报 `rg ...` 失败。

根因：
1. Android 无可用 Linux sandbox 后端（bwrap/landlock 不可用），workspace-write
   必然失败；
2. rootfs PATH 没有 rg，`@vscode/ripgrep-linux-arm64` 的二进制未被发现；
3. 权限默认值来自 base composition 的 `permission` 配置，仅改 Settings 的
   `settings.yaml` 不生效（新会话仍 workspace-write）。

修复：
- ProviderConfig 在 profile patch 覆盖 `permission`：
  `defaultPreset: danger-full-access`，并保留只读/工作区/完全权限三档；
- HostKeepAliveService 设置 `DSH_PERMISSION_MODE=danger-full-access`，保持审批策略一致；
- rootfs `/opt/node24/bin/rg` 软链到 packaged ripgrep。
- 验证：fixed6 保存 Provider 后新建会话直接“完全权限”；真实任务可执行
  `pwd/ls`、写文件、读取、相对 glob、diff（ui-61、ui-75）。

绝对路径 glob 修复（fixed8）：
- 现象：`glob(path="/home/...")` 报 `rg ... No such file or directory`。
- 根因：dsh Host 不在 chroot 内，rg 子进程按 Android 根解析 `/home`；而
  `existsSync("/home/...")` 被 Cortex 的 LD_PRELOAD hook 映射为 true，不能靠
  “路径是否存在”判断。
- 修复：在 `dsh-tool-fs-search` 的 `runRipgrep` 里，把 `/home`、`/tmp` 和
  实际不存在的绝对路径参数映射到 `CORTEX_ROOT` 下；脚本
  `scripts/patch-rootfs-fs-search-paths.sh` 幂等应用。
- 验证：fixed8 上绝对路径 glob 返回 hello.txt；输出仍是物理路径
  `/data/user/0/.../rootfs/home/...`，属显示层小问题，不影响读取。

## 2026-11-09 fixed10：横屏键盘把会话顶出视口

现象：竖屏键盘正常；横屏弹出键盘后会话正文/输入框全部消失，只剩头部和底栏
（ui-88）。仅加 `windowSoftInputMode=adjustResize` 无效（ui-89）。

根因：Activity 在 `configChanges` 中声明了 `orientation|screenSize`，旋转时 WebView
不重建，仍按竖屏高度布局；横屏可用高度被键盘压缩后，页面底部（输入框）落在
WebView 可视区之外，滚动也到不了。

修复：从 `configChanges` 移除 `orientation|screenSize`（保留 keyboard/uiMode），
让旋转重建 Activity/WebView；同时保留 `adjustResize`。
验证：fixed10 横屏正文、输入框、发送按钮完整可见（ui-90、ui-91）。

副作用：旋转会重建 Activity，会话状态由 Host/本地存储恢复；已实测不丢会话。
